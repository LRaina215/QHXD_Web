# 网页地图上传

地图上传将浏览器选择的 NVMP 文件经云网关、RK 后端和 fpga_bridge 发送到 FPGA，并根据地图 ACK 展示进度。独立预览用于查看地图内容。

场地视图右上角新增“上传地图”。选择已转换好的 `.nvmp` 后，点击“上传并下发”，即可通过云网关和RK桥接写入FPGA地图RAM，不需要再SSH拷文件。

## 使用流程

1. 在右上角设置访问Token，连接真实机器人。FPGA必须在线且空闲；若有运行或暂停的任务，先取消。上传不会自动解除运行急停、重启机器人或启动任务。
2. 点击场地栏的“上传地图”，选择 `.nvmp` 文件，再点击“上传并下发”。图片、PCD或PLY点云需要先转换为地图包。
3. 进度是FPGA已经确认的下发字节。数据发完仍最多显示99%，只有最终READY且应答长度正确才显示100%及“地图已加载”。坏CRC、错误profile、超容量、断线和中止会显示原因。
4. 加载成功后刷新场地地图。随后仍需设置实际初始位姿并完成定位对准，才开始导航。上传成功本身不是定位成功。

### 只看显示效果

选择文件后可以点“仅预览”，FPGA离线或处于hold时也能使用。网页会明确显示“预览 · 未下发FPGA”，隐藏机器人、轨迹及任务点位，预览不会替换真实导航地图或发送串口报文。“返回机器人地图”关闭本浏览器预览；成功提交真实下发后也会退出预览。

预览通过同一上传接口的`preview=true`参数校验并生成PNG，保存在RK的`backend/data/map_preview.json`，GET同参数读取。它是网页展示资料，不是FPGA地图READY或定位成功的证据。演示场地图不能直接用来接受真实场地导航。

当前格式固定为SLF128的NVMPv3：48字节头、几何0x0107、profile0x33580001、ZHI350/ZLO−300、18位槽字、最多86064字节。制作工具与量测流程见导航工程的`docs/3_guide/ground_debug_and_mapping_20261027.md`。

关闭窗口不会中断已开始的下发；运行急停可以中止。FPGA复位后地图失效，页面提示重新下发，旧任务不会自动继续。地图文件保存在RK的`backend/data/prior_maps/`，只保留最近5份生成文件；不会写FPGA Flash。

## 接口

| 接口 | 含义 |
|---|---|
| `POST /api/navigation/map/upload?filename=field.nvmp&map_id=yuntuo_field` | `Content-Type: application/octet-stream`，body为文件原字节；返回队列ID及状态 |
| `GET /api/navigation/map/upload` | 返回最后一次下发的状态、文件名、确认字节数、百分比和说明 |

POST沿用公网Token和写请求频率限制。云端和RK都检查实际body长度，不能靠伪造较小Content-Length绕过容量限制。RK使用服务生成的文件路径，客户端不能指定写盘位置。地图内容复用现有FPGA包解析器，桥接仍检查新鲜IDLE和任务状态。

内部`POST /api/internal/fpga/map`继续支持RK本地文件路径，用于维护；网页入口增加`upload_id/filename`关联进度，不另开串口。地图下发期间保活、状态上报和急停处理继续使用原逻辑。
