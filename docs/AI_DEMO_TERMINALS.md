# RK3588 真实业务处理终端

默认观察**网页／小程序现有请求**。观察器不录音、不加载模型、不调用任何任务接口。

在 RK 图形桌面运行：

```bash
cd ~/QHXD
bash scripts/open_ai_demo.sh
```

弹出五个只读窗口：

1. **实际语音识别**：后端真实录音/ASR调用、识别文本、成功/失败与耗时。
2. **实际语言理解**：用户文本、规则或LLM来源、模型输入、实际可见输出、解析结果。
3. **任务下发与FPGA反馈**：待确认编号、确认关联、预检拒绝、桥接请求/响应、NV排队、原传输函数返回、推进的FPGA STATUS与任务反馈。
4. **实际语音合成**：真实回复文本、生成/跳过/失败、音频路径与播放调度。
5. **YOLO26实际视觉识别**：实际模型名、类别、置信度、检测框、颜色、跟踪ID、有效深度对应的机身系坐标和水平距离、检测帧率与结果新鲜度。

只看视觉窗口（也支持SSH）：`bash scripts/open_ai_demo.sh --console yolo`。
视觉窗口每秒通过现有后端的两个GET接口读取状态，不启动检测器、不另占相机、不重启服务。
显示每秒一次不等于模型只跑1FPS；模型检测帧率按现有感知状态显示。无有效深度时距离为null，
单帧NPU推理耗时当前未上报，不拿结果年龄或帧间隔冒充。过期时不把旧目标显示成当前目标。
YOLO是持续检测流，不把每帧强行归到某一条语音请求；相应任务的TARGET报文仍在任务窗口观察。

同一请求用相同 `trace` 编号关联。语音“确认执行”或按钮确认属于另一个 HTTP 请求，通过 `related_trace` / `pending_command_id` 关联原请求。

默认只显示启动观察器之后的新事件，不把历史日志充当实时处理。加 `--history` 查看已有记录。SSH下可以运行：

```bash
bash scripts/open_ai_demo.sh --console all
```

安装／更新桌面入口“云拓真实处理流程”：

```bash
bash scripts/open_ai_demo.sh --install-desktop
```

## 与实际业务相同的边界

- 网页点导航按钮通常不经过ASR/LLM。文字输入不经过ASR。小程序使用微信识别时，识别发生在手机，不冒称RK识别。只有业务调用对应模块时才出现该模块事件。
- 当前Qwen3关闭思考模式，只展示实际可见模型输出和决策结果，不生成“内部思考”字幕。
- 规则命中会显示规则来源；模型调用失败、规则回退、守卫拒绝、等待确认均如实显示。
- `nv.queued` 只表示原报文进入原队列；`nv.transport.sent` 只表示原传输函数成功返回。两者都不是CPU应用层执行ACK，也不能证明已经到达或停稳。反馈事件来自原有状态机。
- TTS播放调度返回不代表扬声器已播完。日志耗时按函数实测，不虚构逐token输出。
- 关闭观察窗口只停止读日志，不停止服务、不中断任务。用户继续从原网页／小程序操作。

## 后端与桥接日志

现有业务通过 `yuntuo.trace_backend:app` ASGI入口与 `yuntuo.trace_bridge` 桥接入口增加只读观测；原路由、模型实例、守卫、状态机、队列与报文保留。业务方法只调用一次，原返回对象和异常继续原样传递。后端到桥接HTTP附加 `X-Yuntuo-Trace` 请求头，仅用于关联，不增加NV载荷、不更改固件。

日志为 `logs/processing_backend.jsonl` 和 `logs/processing_bridge.jsonl`，每个文件4MiB、两份轮转备份。进程内有界队列1024条，后台线程写入；满时丢日志并记录丢失数量，不让磁盘写入阻塞控制链。日志包含用户输入和回复，文件权限600；不记录API密钥或认证头。默认不通过公网API暴露详细日志。

`YUNTUO_PROCESS_TRACE=0` 可关闭事件写入；恢复原启动入口可完全撤下观察包装。`bash scripts/open_ai_demo.sh --check` 只查看日志是否生成。
